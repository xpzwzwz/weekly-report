# 「具身智能 + 大模型」五路进展周报

**时间范围：2026-08-04—2026-08-10（北京时间；截至 08-10）**

## 第一路｜VLA / 遥操作 / 具身数据

### ✅ 已核实要点

- **2026-08-06｜In-Context VLA**：提出“只消费、不生成”具身语言的 VLA 后训练框架，通过结构化感知上下文和检测、深度估计、VLM 等工具调用辅助动作预测；论文报告在 RoboCasa-GR1、SimplerEnv、LIBERO 及 8 项真机任务上优于匹配配置的 CoT 方法【自报】。[arXiv:2608.05738](https://arxiv.org/abs/2608.05738)
- **2026-08-08｜SGLang v0.5.17 提供 Kimi K3 日首支持**：支持其多模态视觉塔、1M 上下文、MXFP4 权重以及 DCP、推测解码和量化权重 LoRA；已在 NVIDIA GB300、AMD MI35x 验证【自报】。这是部署适配，不是新的机器人策略模型。[GitHub Release](https://github.com/sgl-project/sglang/releases/tag/v0.5.17)
- **截至 2026-08-10｜大厂与数据侧**：经核查 Google DeepMind、NVIDIA Robotics、1X 等官方发布页，本周未发现新的 VLA、遥操作系统、触觉/灵巧手方案或正式发布的真机数据集与 benchmark；**本周无更多可核实新动态**。[Google DeepMind](https://deepmind.google/blog/) / [NVIDIA Robotics](https://developer.nvidia.com/blog/blog/category/robotics/) / [1X](https://www.1x.tech/discover)

### ⚠️ 传闻

- 本周未发现达到收录价值、且能由可信二手来源交叉确认的机器人公司新品传闻。

### 本周最值得关注的 2–3 项

1. In-Context VLA 将语言定位为动作策略的“输入证据”，而非高延迟 CoT 输出。
2. VLA 开始进入通用高吞吐推理框架的正式模型支持矩阵。
3. 本周机器人硬件、遥操作和新数据集方向发布偏少，不宜用旧消息补位。

## 第二路｜多模态大模型

### ✅ 已核实要点

- **2026-08-08｜SGLang v0.5.17 完成 Kimi K3 多模态部署支持**：官方发布说明确认其 2.8T 参数 LatentMoE、MoonViT3d 视觉塔、1M 上下文和原生 MXFP4 checkpoint；参数、吞吐与硬件验证数字均为项目方披露【自报】。[GitHub Release](https://github.com/sgl-project/sglang/releases/tag/v0.5.17)
- **2026-08-08｜MiniMax-H3 进入 SGLang-Diffusion**：支持文本生成视频与同步立体声、首尾帧条件以及图像/视频/音频参考条件；项目方称已在 B200、H100 和双 RTX 5090 上验证【自报】。[GitHub Release](https://github.com/sgl-project/sglang/releases/tag/v0.5.17)
- **截至 2026-08-10｜主流实验室发布面**：OpenAI、Anthropic、Google DeepMind、Qwen 官方页未显示本周新增、日期可精确核实的通用 VLM 正式发布；**本周无更多可核实新模型动态**。[Anthropic News](https://www.anthropic.com/news) / [Google DeepMind News](https://deepmind.google/blog/) / [QwenCloud Changelog](https://docs.qwencloud.com/changelog/models)

### ⚠️ 传闻

- **2026-08-07｜OpenAI “Astra”延期说法**：Axios 报道 OpenAI 因网络安全能力风险扩大测试并放缓一款内部代号为 Astra 的未发布模型。OpenAI 尚无正式模型发布页或模型卡，故不将名称、能力或发布时间视为已确认发布。[Axios](https://www.axios.com/2026/08/07/openai-astra-model-delay-cybersecurity-risks)

### 本周最值得关注的 2–3 项

1. 多模态推理栈正同时覆盖超大视觉语言模型和视频—音频联合生成模型。
2. MiniMax-H3 的多条件、同步音频服务化支持值得跟踪实际吞吐与显存数据。
3. “Astra”目前只能按未发布模型传闻处理。

## 第三路｜部署 / 推理 Infra

### ✅ 已核实要点

- **2026-08-08｜SGLang v0.5.17 发布**：包含 582 个 PR、194 位贡献者【自报】，新增 Kimi K3、MiniMax-H3、EmbeddingGemma、LFM2.5 embedding 等模型支持。[GitHub Release](https://github.com/sgl-project/sglang/releases/tag/v0.5.17)
- **2026-08-08｜原生 Rust 服务前端初版**：将网络接入、请求校验、tokenizer manager 和响应输出迁移到多线程 Rust 实现，同时提供 OpenAI 兼容 API、PD 分离及预编译产物。[GitHub Release](https://github.com/sgl-project/sglang/releases/tag/v0.5.17)
- **2026-08-08｜DWDP MoE Prefill 并行**：通过 NVLink P2P 预取其他 GPU 的专家权重并在本地计算，绕开 EP all-to-all token dispatch；项目方在 4×B200、gpt-oss-120b 上报告最高 1.92× 提升，并明确标注为早期开发功能【自报】。[GitHub Release](https://github.com/sgl-project/sglang/releases/tag/v0.5.17)
- **2026-08-08｜会话引用感知 Radix Cache**：请求可携带稳定 `session_id`，缓存淘汰时保留活跃会话仍引用的前缀，主要面向多轮 agent 和 RL rollout 服务。[GitHub Release](https://github.com/sgl-project/sglang/releases/tag/v0.5.17)
- **2026-08-08｜推测解码与恢复路径优化**：降低混合线性注意力模型 MTP decode 的主机侧空隙；另加入 GPU 权重缓存 daemon，以减少大模型服务重启时重复加载权重的成本。[GitHub Release](https://github.com/sgl-project/sglang/releases/tag/v0.5.17)
- **2026-08-08｜DeepSeek-V4 SM90 FP8 MegaMoE 路径**：新增 DeepGEMM MegaMoE A2A、预分发 JIT kernel 和 FP8 专家权重准备，当前需环境变量显式开启。[GitHub Release](https://github.com/sgl-project/sglang/releases/tag/v0.5.17)

### ⚠️ 传闻

- 本周无值得单列的推理基础设施传闻。

### 本周最值得关注的 2–3 项

1. Rust 前端表明推理框架优化范围正从 GPU kernel 延伸到网络与 tokenization 热路径。
2. DWDP 尝试以“搬运权重”替代“搬运 token”，可能改变高带宽互联节点上的 MoE prefill 并行设计。
3. 会话感知 Radix Cache 直接针对长生命周期 agent 与 RL rollout 的缓存命中问题。
